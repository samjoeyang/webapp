## 1. 两条素材路线

先判断用户给的是「书名」还是「全书文件」，再选路线：

| 路线 | 触发条件 | 素材来源 | 优点 | 局限 |
|---|---|---|---|---|
| A. 公开解读版（快） | 只给书名/作者 | 联网搜索：豆瓣、公开书评、读书笔记、已公开解读稿；交叉 2 个以上来源 | 速度快、无需原书、token 消耗低 | 属二次转述，易有偏差；不能替代通读；受来源质量影响 |
| B. 全书解析版（准） | 上传 PDF/EPUB/MOBI/AZW/AZW3/TXT/DOCX/FB2/图片扫描件 | 文件解析提取文本；图片版先 OCR；Kindle 系格式先转换/解析出纯文本；超长文本切块后分批处理；**默认全文逐块读完，不得跳章**；仅用户明确指定单章/多章时，才只遍历选定章节（范围规则见 `scope-boundary.md`） | 忠于原书，可回溯章节 | 耗时更长、token 消耗高；需处理版权与扫描质量 |

### 路线判定顺序（节点 1 入口，固定流程）

```
检查本次输入是否带上传文件（PDF/EPUB/TXT/扫描件）
  ├─ 有文件且可正常解析 → 路线 B（全书解析）
  ├─ 有文件但解析失败 / 加密 / 乱码 → 转路线 A，按 source-collection.md 平台优先级检索
  └─ 无文件 → 路线 A（公开解读）
```

### 混合策略触发规则（方案乙）

- 默认只走单一路线，不自动跨路线切换。
- 走路线 A 时若素材偏薄（试读/目录为主、缺少可回溯的章节论据），主动提示用户一次：可上传原书转路线 B 校正；是否补传由用户决定。
- 用户在流程中主动补传原书后，再从 A 转 B 校正；两种路线的成稿结构保持一致。

路线 A 的具体采集步骤（国内电子书平台按可读正文量的优先级排序、搜索与浏览器读取、登录/付费墙处理、来源留痕）见 `source-collection.md`。

### 素材门槛与降级标准

**足够成稿：**
- 路线 A：拿到全书目录，且主要章节有可见试读或官方解读；或至少 2 篇可回溯的长书评/解读稿，足以重建主线并支撑 3~5 个重点；核心观点有第一层来源可回溯。
- 路线 B：解析正文覆盖全书主体，章节结构可辨，全部切块进入分章摘要（见第 2 节）。

**素材不足：** 只有简介/目录/短评而无章节级论据；可用来源互相矛盾且无法印证；路线 B 正文残缺、缺章少节拼不出主线。

**降级动作（不硬凑）：**
1. 明确告知用户实际读到的范围与具体缺口；
2. 给出选项：a) 接受基于现有素材的公开解读稿，缺口全部进「存疑待核」；b) 上传原书转路线 B 校正；c) 终止本次生成；
3. 素材不足时不得编造章节细节补全主线。

## 2. 分层蒸馏四步

禁止一次性把全书压成一篇稿，必须分层：

1. **分块摘要**：每一章（或切块）单独提炼：核心论点、关键案例、数据/金句；不展开评论。路线 B 默认遍历 `chunks.json` 全部切块，逐块出摘要，不跳过前言/附录/任一章节；用户明确指定局部章节时，只遍历选定范围内的切块，未选定章节不进入摘要；合并时核对切块数与已摘要数一致。
2. **主线合并**：把各章摘要合并，梳理全书论证主线：作者要解决什么问题 → 怎么论证 → 得出什么结论。
3. **二次压缩**：砍掉次要案例与细节，按目标时长（默认 3~5 分钟口播）控制篇幅；保留主线与 3~5 个重点。
4. **成稿重排**：按统一结构润色成流畅口播稿（见 `../assets/brief_template.md` 与 `prompts.md`），并标注可回溯的章节出处。

## 3. 节点编排方式

### 3.1 简易版（普通智能体）
系统提示词 + 搜索工具 + 文件读取工具 + 知识库；适合单稿、轻量场景。

### 3.2 工作流版（推荐，可复用）
拖拽节点串联：

```
输入(书名/文件)
  → 素材获取(搜索 / 文件解析)
  → 切块(split_chapters.py)
  → 分章摘要(并行/串行 LLM 节点)
  → 主线合并(LLM 节点)
  → 压缩成稿(LLM 节点, 控制字数/时长)
  → 事实校验(LLM 节点, 对照素材核对)
  → 定稿输出(Markdown / 口播稿)
  → [可选] 配音 → 字幕 → 配图/视频 → 合成
```

### 3.3 多智能体分工
- 拆书智能体：分章摘要与主线；
- 成稿智能体：按口播风格重写；
- 审核智能体：核对事实、时长、结构完整性，标注存疑处。

## 4. 模型与上下文选择

- 长文本优先选长上下文模型；上下文放不下全书时，切块分批处理，用摘要累积代替一次性载入。
- 切块大小参考 `split_chapters.py --max-chars`（默认 1500 字），按所选模型上下文窗口调整。
- 摘要环节可用较小模型降本；成稿与校验环节用质量更高的模型。
- 涉及检索时按章节/关键词定位，不要靠模型凭记忆补全书中细节。

## 5. 校验与防幻觉

定稿前必须过校验节点，逐条核对：

- 每个核心观点能否在素材（原书章节或搜索来源）中找到依据；找不到依据的观点删除或标注「存疑」；
- 不得编造书名不存在的案例、数据、人名、金句；
- 区分「作者原意」与「解读者引申」，成稿中明确标注；
- 篇幅达标：用 `../scripts/estimate_duration.py` 校验口播时长；
- 来源留痕：路线 A 记录引用来源；路线 B 记录对应章节。

## 6. 本环境执行映射

| 链路环节 | 当前环境可用方式 |
|---|---|
| 搜索公开资料 | 通用联网搜索工具；多来源交叉 |
| 文件解析 | PDF/EPUB/TXT 读取；扫描图片先 OCR；长文本走 `scripts/split_chapters.py` |
| 分章摘要 / 合并 / 成稿 | 本智能体按 `prompts.md` 模板逐节点生成 |
| 时长校验 | `scripts/estimate_duration.py` |
| 字幕与分句 | `scripts/script_to_srt.py` |
| 配音风格预设 | `references/voice-presets.md` 锁定统一音色 profile |
| 配音分段拼接 | `scripts/concat_audio.py` 统一格式并无损合并 |
| 配图 / 视频生成与后期 | 见 `video-pipeline.md` |

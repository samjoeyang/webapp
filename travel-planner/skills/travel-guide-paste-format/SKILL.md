# 旅游攻略粘贴格式（TPF v1）

把旅游攻略输出成「旅途」App 可直接粘贴的格式。用户把代码块整段复制，在 App 页面**任意位置直接粘贴**（Ctrl+V / 长按粘贴），即自动识别并创建行程。

## 一、何时必须按本格式输出

| 场景 | 要求 |
|---|---|
| 用户说「生成 XX 地旅游攻略/行程/旅行计划」 | 正文攻略 + **文末必须附带 TPF 粘贴块** |
| 用户说「导入到旅途 App / 粘贴进行程 / 按导入格式输出」 | 只输出 TPF 粘贴块（可附极简说明） |
| 用户只要文字版攻略、明确不要导入 | 正常 Markdown 输出，**不必**附 TPF 块 |

粘贴块必须整体放在**一个 Markdown 代码块**里（``` 包裹），用户复制块内全文、在 App 页面任意位置粘贴即可自动创建行程；无关内容粘贴不会触发识别。

## 二、铁律（违反任何一条都会导致粘贴失败）

1. TPF 块整体放在**一个 Markdown 代码块**里（``` 包裹），用户复制块内全文。
2. **首行必须是与列对齐的 `旅途行程 v1`**（可带前后空格，不能改字）。
3. 每行一条记录，行类型用方括号标签开头：`[Day]` / `[Node]` / `[Transport]` / `[Lodging]` / `[Packing]`。
4. 字段之间用 ` | `（竖线 + 两侧空格）分隔；**「描述」等自由文本内绝对不能出现 `|`**，改用 `；`。
5. `[Node]` 必须归属某个 `[Day]`（先写 Day 再写其下 Node）。
6. 时间用 24 小时制 `HH:MM`；花费填纯数字（单位：元/人），未知填 `0`。
7. 不要输出本规范之外的任何行；拿不准的字段留空，不要编造固定值以外的内容。

## 三、格式规范

### 1. 行程信息（可选，放在 [Day] 之前，`键: 值` 形式）

```
名称: 京都赏枫五日游
目的地: 京都
图标: 🍁
天数: 5
晚数: 4
出发日期: 2026-11-15
```

- `名称` 缺省「未命名行程」；`目的地` 缺省取名称；`图标` 可留空；`天数/晚数` 缺省按 Day 数量推算。
- `出发日期` 支持 `2026-11-15` / `2026/11/15` / `2026年11月15日`；不确定就**不要写这一行**（App 内可后补）。

### 2. 每日日程

```
[Day] 第一天标题 | 当天所在城市
[Node] 10:00 | ✈️ | 节点标题 | 地点 | 人均花费 | 描述
```

- `[Day] 标题 | 城市`：城市可留空（留空则沿用 App 内上一天城市逻辑）。
- `[Node]` 字段顺序固定：**时间 | 图标 | 标题 | 地点 | 花费 | 描述**。
  - 时间、图标可省略，但省略时**不能跳字段**：`[Node] 09:00 | 📍 | 清水寺` 合法；`[Node] 清水寺` 也合法（时间默认 09:00、图标默认 📍）。
  - 标题必填；地点/花费/描述可整段省略。
  - 描述写玩法提示、预约方式、推荐菜等，**一句话内不要换行、不要含 `|`**。
- 节点按时间先后排列（App 也会自动排序）。

### 3. 交通（可选，可多行）

```
[Transport] plane | 去程 | 北京 | 大阪 | CA927 | 09:00 | 13:00 | 1200 | true
```

字段：`类型 | 行程段 | 出发地 | 到达地 | 航班/班次 | 出发时间 | 到达时间 | 票价 | 是否已订`

- 类型：`plane`（飞机）或 `train`（高铁/火车）。
- 行程段：**去程 / 在途 / 返程** 或自定义（如「中转停留」）。
- 末位 `true` = 已订，`false` 或留空 = 待订。
- 段内信息（如行李额、选座）写不进这里，放描述里没有对应字段——**交通没有描述字段**，重要信息放 Day 的 Node 描述。

### 4. 住宿（可选，可多行）

```
[Lodging] 京都站前酒店 | 京都 | 酒店 | 4 | 800 | 京都站八条口 | true
```

字段：`名称 | 城市 | 类型 | 晚数 | 价格/晚 | 地址 | 是否已订`

### 5. 行李清单（可选，可多行；同一分类写多行会自动合并）

```
[Packing] 证件资金 | 护照, 身份证, 信用卡, 日元现金
[Packing] 衣物 | 羽绒服, 围巾, 舒适步行鞋
[Packing] 药品健康 | 肠胃药 x1, 创可贴 x1
```

- 物品之间用 `,`（中英文逗号、顿号均可）分隔。
- 数量后缀：`物品 x2` / `物品*2` 会识别为数量 2，缺省 1。

## 五、输出前自检清单

- [ ] 代码块首行是 `旅途行程 v1`
- [ ] 每个 `[Node]` 都跟在某个 `[Day]` 后面
- [ ] 所有自由文本（标题、地点、描述、地址）中没有 `|` 字符
- [ ] 时间是 `HH:MM`，花费是数字
- [ ] 图标是单个 emoji（如 ✈️ 🏨 🍜 📍 ⛩️）
- [ ] 没有虚构的确定信息：不确定的票价/时刻留 `0` / `待定` 或省略字段

## 六、与 App 功能的对应关系（生成时心里有数）

| TPF 字段 | App 内位置 |
|---|---|
| 名称/图标 | 顶栏行程下拉、总览大标题 |
| 目的地 | 总览横幅（天气/汇率跟随该城市） |
| 出发日期 | 总览倒计时、逐日映射具体日期、自动生成 D-7/D-3/D-1/D0 提醒 |
| [Day]/[Node] | 「每日行程」时间轴（节点可后补图片，实现图文混排） |
| [Transport]/[Lodging] | 「交通住宿」页（可逐个/批量标记已订） |
| [Packing] | 「行李清单」页（计入打包进度；保险也是普通分类，可写 `[Packing] 购买旅行保险 \| 旅行意外险, 医疗救援险`） |

注意：**图片无法通过粘贴传递**，图文混排的图片需在 App 内节点编辑时手动添加；TPF 只负责文字与结构。

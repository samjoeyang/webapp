## 会议签到接入 UNOAuth 统一登录（BFF 会话模式）

方案定型：参考微信网页授权 / django-allauth / django-oauth-toolkit 的共同范式——**服务端持 secret、浏览器只拿自有会话**。会议签到保持匿名扫码，仅"管理会议"需登录（或沿用原 x-admin-pass 口令）。auth.zhenzhidaole.com 与 legaldata 均**未改动**。

关键事实链（源码/线上核实）：
- UNOAuth token 端点线上 discovery 仅 `client_secret_basic/post`、`private_key_jwt`，无 `none` → public client 免 secret 路线不可行（除非改认证服务）。
- introspect 端点强制 client 凭据且按 client 隔离（`userHandles.js`）→ 验 token 绕不开服务端 secret；JWKS 本地验签虽可行但 access_token 是否 JWT 未实测。
- utils_api 已有现成 BFF：`/unoauth/login`→`/callback`→签发 `uno_session`（HttpOnly/SameSite=Lax，7天）+ `/unoauth/me`。同站跨子域（webapp 与 utils.api 同 eTLD+1）fetch 带 `credentials:'include'` 时 cookie 自动随行。

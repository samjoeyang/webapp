## macos-system-cleaner v2.3.0：补 Rust/C++/PHP 开发环境清理（commit 9f629de）
- **新增类目**：`rust_junk`（cargo 项目 target/ 构建产物，caution 逐目录确认）、`cpp_junk`（ccache/sccache/Conan 1/2/vcpkg 缓存 + build/builddir/cmake-build-*/out/obj/bin/CMakeFiles 构建目录，caution 逐目录确认）、`php_junk`（~/.composer/cache、~/.cache/composer、~/Library/Caches/composer + vendor/，caution 逐目录确认）。
- **扩展既有类目**：`npm_junk` 加 Electron 缓存（~/.electron、~/.cache 与 ~/Library/Caches 的 electron/electron-builder）与 ~/Library/Caches/Yarn；`python_junk` 加 ~/.pyenv/cache；`xdg_cache`/`user_cache` 排除表同步补新归属子目录；`misc_pkg_cache` 移除 Composer（避免与 php_junk 重复计数）。
- **关键修复（新通用防护）**：`collect_named_dirs` 加环境目录防护——位于 .venv/venv/env/virtualenv/node_modules/vendor/target/site-packages/__pycache__/.git 内部的同名子目录一律跳过。起因是实测 `cpp_junk` 把 `workspace/.venv/bin`（venv 的解释器入口）误判成 C++ 构建产物，不防护会删坏环境本体。
- **共用基建**：DEV_BASES 提为模块级常量（npm/Python/Rust/C++/PHP 五类共用）；新增 `custom_named_dirs` 收集器（缓存整体 + dev_bases 内按名查找，深度≤2）。
- **检查结论（用户问的核对项）**：python/npm 原本就覆盖缓存+过程产物（venv/node_modules），本次只小补；Electron 原本只被 user_cache/xdg_cache 兜底偶然覆盖，现已专类归属 npm_junk。
- 四副本同步完成：源 → ~/.workbuddy/skills → public/skills → zip（Python zipfile，本包全 ASCII 名故无 UTF-8 置位，正常）→ npm run build。本机实测：php_junk 3 项 30.2MB，npm_junk 672MB（unoAuth node_modules），cpp/rust_junk 本机 0 项（无 cargo/C++ 工程）。

## 门户卡片：介绍文字展开/收起（2026-10-30，commit cc3baa9）
- 起因：某技能的描述极长，Skill 卡在手机端高到需要滚很久。用户要求**只针对介绍文字**加「展开/收起」文字链接。
- 实现 `src/App.jsx` 的 `Desc` 组件：默认折叠（应用卡 4 行、Skill 卡 5 行，`-webkit-line-clamp`），**只有真正溢出**（`scrollHeight - clientHeight > 2`）才渲染「展开/收起」，短文案卡片不出按钮；`ResizeObserver` 跟随宽度变化重测；展开态不再测量以免按钮消失；带 `aria-expanded`/`aria-controls`。
- 隔离卡片点击：按钮 `onClick` 里 `preventDefault + stopPropagation`、`onKeyDown` 里 `stopPropagation`，不会误触发 Skill 卡复制提示词或应用卡跳转。
- 结构改动：应用卡从「整块 `<a>`」改为 `div.app` + `.go.stretch` 链接伪元素铺满整卡（`inset:0`），**避免 `<a>` 内嵌 `<button>` 的非法结构**，整卡点击行为不变；折叠按钮 `z-index:1` 压在铺满层之上。
- 布局坑：`.desc` 原本 `flex:1`，折叠后会被拉伸撑高导致 clamp 无效感 → 去掉 `flex:1`，改 `.go{margin-top:auto}` 兜底，同行卡片底部仍对齐。
- **顺手修掉截图里暴露的文案重复**：Skill 卡底部原本显示「点击复制安装提示词 · 点击复制安装提示词」——CSS `.skill .go::after` 与 JSX 各写了一次，删除 CSS 基础 `::after` 内容，仅保留「已复制 ✓」状态。
- 验证：`npm run build` 通过；用本机 Chrome `--headless=new --dump-dom` 抓渲染后真实 DOM，确认 30 个描述全部初始折叠、**恰好 6 个出现「展开」**、短文案卡片无按钮、占位节点已被 React 清空、「点击复制安装提示词」由 38 次降为 19 次（每卡一次）。

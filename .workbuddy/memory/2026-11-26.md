## API 设计定稿（2026-11-26）
- Base `https://utils.api.zhenzhidaole.com/v1/cleaner`，单域；不启用 auth 子域。MCP tokenSchema 让用户输入 license key，注入 `Authorization: Bearer`，`device_id` 作为工具参数。
- 端点：`POST /auth/activate`、`POST /auth/refresh`、`GET /entitlement`、`GET /manifest`、`POST /bundles/{version}/download-url`、`GET /bundles/{version}/download?exp&device&sig`、`POST /usage`、设备吊销。
- **关键调整**：不把密文/DEK 回传进 MCP 工具结果（会污染上下文）。MCP 只返回短的签名下载 URL（60s、单次、绑设备）；`client.py` 用 curl 下载，服务端解密后经 TLS 返回明文规则包，本地按 manifest 的 SHA-256 + Ed25519 校验后原子切换。加密只保静态存储，不承诺 DRM。
- `device_id = sha256(IOPlatformUUID + 固定 salt)`，原始 UUID 不出本机；每 license 3 台，可吊销。
- manifest 签名用 Ed25519，规范 JSON（排序键、无空白），签名覆盖 schema/product/version/published_at/files/bundle.sha256/size，不含 URL；公钥 pin 在本地包。
- 错误信封 `{error:{code,message,retryable,request_id}}`；限流：activate 5/min/IP，manifest 60/min/device，download-url 10/min/device，usage 20/min/device。
- Serverless 用 Postgres（license/device/usage）+ 私有 Blob/R2（bundle.enc）；主密钥与签名私钥只在 Vercel env，禁 SQLite/硬编码密钥。

## License key 生成方案
- 格式：`MSC2-XXXX-XXXX-XXXX-XXXX-CCCC`。`MSC`=产品，`2`=格式版本；payload 10 字节 CSPRNG（80-bit），Crockford Base32 16 字符；CRC-16/CCITT 4 字符只做 typo 检测，不是安全强度。
- 服务端**只存** `HMAC-SHA256(pepper, normalize(key))` 与指纹/前缀；pepper 在 Vercel env。禁存明文、禁写日志/仓库/专家包；丢失靠吊销重发，或用管理员公钥封存一份密文 escrow。
- 校验：normalize（去分隔符、大写、O→0/I/L→1/U→V），算 HMAC 查库，再校验设备绑定（≤3 台）。CRC 失败直接 `INVALID_LICENSE`。
- 发放：支付 webhook 可用则实时生成+一次性展示；否则预生成池，人工发。吊销走状态字段，不复用同一 key。未来格式升级用 `MSC3`。

## 三套餐授权模型（买断/订阅/试用）
- plan **不编码进 key**，三种共用 MSC2 格式；服务端 `plan` + `status` + `expires_at` 决定。买断 `expires_at=NULL`；订阅=周期末，续费失败进 `past_due` 7 天；试用=首次激活+14 天（签发时不走表），不可续，升级时换发新 key 并把旧 key 置 `upgraded`。
- 设备上限：试用 1 台、付费 3 台；订阅到期 90 天内续费可复用原 key，超过 90 天或已吊销则发新 key。
- `effective_access`：active/past_due=full，expired=read_only（只读扫描+缓存规则，禁清理/下载），revoked/upgraded/suspended=none。
- 高风险清理需 15 分钟 Ed25519 授权回执（signed entitlement receipt），过期或离线超 30 天只能只读；回执只含指纹/设备/权限/exp，不含路径。
- 新增端点：`POST /admin/licenses`、`POST /webhooks/payment`（事件 ID 幂等）、`POST /admin/licenses/{id}/upgrade`；`/auth/activate` 与 `/entitlement` 增加 plan/status/expires_at/effective_access/days_remaining；download-url 要求 full。
- 新错误码：`TRIAL_EXPIRED` / `SUBSCRIPTION_PAST_DUE` / `SUBSCRIPTION_EXPIRED` / `LICENSE_UPGRADED` / `PAYMENT_REQUIRED` / `GRACE_EXCEEDED`。

## Vercel API + Cloudflare KV 可行性（2026-11-26）
- 官方明确支持从外部经 REST API/SDK 访问 Workers KV（FAQ last updated 2026-11-24），但 binding 更快、REST 写限流更低且共享 Cloudflare REST API 限额。KV 为最终一致，缓存旧值可持续到 cache TTL（最小 30s）；同 key 并发写 last-write-wins；同 key 写上限 1/s。限制页 last updated 2026-10-30：Free 100k 读/日、1k 写/日、25MiB/value。
- 结论：**KV 只能做读多写少的配置/清单缓存，不能当 license/device/nonce 的真相源**。设备上限需原子条件更新、吊销需即时生效、nonce/限流计数需原子自增——KV 都不支持。建议 Vercel Functions + Postgres（Neon/Supabase）为唯一真相源，密文包放 R2/Blob，KV 只缓存 manifest/公钥；若坚持全 CF，则把 API 迁到 Workers 用 binding + D1/DO + R2。
- Workers KV Instant（2026-10-01 发布）虽改善一致性与延迟，但仍私有 beta、1 写/s/namespace、1MB/namespace，不能作为当前方案依赖。

## Vercel 方案 vs Cloudflare 方案对比（2026-11-26）
- 结论：**维持 Vercel（Pro）为首选**；Cloudflare 全套仅在愿意重写并接受 D1 单线程模型时才更优。
- Vercel：现有 `utils_api` 已走 Vercel CLI 部署，零迁移成本；Node.js 生态直接可用；Postgres 事务适合 license/device/nonce。注意 **Vercel Hobby 条款 §5 禁止商业使用**，且 Hobby/Pro trial 默认允许用 Your Content 训练模型（ToS §1，更新 2026-10-19），本产品收费必须上 Pro（$20/月起）。Vercel Postgres 已下线（docs 更新 2026-01-13），新项目走 Marketplace Neon/Supabase；Vercel KV 已弃用，用 Upstash Redis。Functions 默认单区 iad1，req/resp body 4.5MB，Hobby duration 300s，Pro 可 800s。
- Cloudflare：Workers Paid $5/月起，含 10M 请求/月 + 30M CPU ms；KV binding 原生低延迟、R2 免费 10GB/月 + 无 egress；D1 单库单线程（1ms 查询约 1000 QPS）、免费 500MB/库、5GB/账号；强一致原子操作用 Durable Objects。代价：从 Node.js 迁到 Workers runtime、DNS/部署流程全换，需重写 crypto 等调用。
- 两者均为境外服务；大陆用户访问需实测，不做稳定性假设。

## 只考虑免费方案的结论（2026-11-27）
- **Vercel Hobby 不可用于本产品**：Vercel ToS §5 明确 Hobby 仅 personal/non-commercial（更新 2026-10-19）；license 收费属商用，且 Hobby/Pro trial 默认允许内容用于模型训练。即使配外部免费 DB 也不合规。
- **Cloudflare Free 是唯一合规免费路径**：其 ToS（更新 2025-09-12）未设 non-commercial 限制，但 §2.2.1(h) 禁止在接收 Free Services 的站点处理/收集信用卡信息 → 支付页必须由外部 provider 托管，Worker 只接收签名 webhook；§2.6 免费服务可随时终止、无责任保证。
- CF Free 栈：Workers（10 万请求/日、10ms CPU/请求、50 subrequests、128MB）+ D1（500MB/库、10 库/5GB、500 万行读/10 万行写/日）+ SQLite-backed Durable Objects（10 万请求/日，做 license 原子绑定/nonce）+ KV（10 万读/1000 写/日，仅 manifest 缓存）+ R2（10GB/月、无 egress，存 bundle.enc）。Custom Domain 需把 `zhenzhidaole.com` zone 接入 CF，可自动签多级子域证书。
- 风险：10ms CPU 硬上限，超限直接报错；免费服务无 SLA，必须保留客户端 30 天离线缓存 + D1 定期导出。

## 域名拆分可行性（用户拟用 utils.api + auth 双域）
- 本机 dig 两个域均返回 198.18.x.x（RFC2544 保留测试段），属沙箱 DNS stub，**不能据此判断真实解析**；需到 DNS 服务商核对。
- 结论：技术上可行但**首推单域** `utils.api.zhenzhidaole.com` 路径分区 `/v1/auth/*`、`/v1/cleaner/*`。client.py 非浏览器，无 CORS/cookie 问题；拆域导致双 Vercel 项目、双密钥边界、双故障面。
- 仅当未来多产品统一 SSO 时，才让 `auth.zhenzhidaole.com` 做独立 OIDC IdP（建议接现成 IdP 自定义域，不自建），API 域用 JWKS 验 JWT；流程用 Authorization Code + PKCE（RFC 9700, 2025-01；datatracker 显示 last updated 2026-05-20），refresh token 轮换存 Keychain。
- 更优「保留目标 v2」：**scripts 全量本地可审，只远程加密下发 rules/*.json 与 references/**（数据而非代码/指令），复用现有 `scan.py --rules-dir`；需改 SKILL.md「不要加密规则」表述。审核面清晰，同时隐藏真正核心规则库。
- Vercel 官方限制（https://vercel.com/docs/functions/limits，检索 2026-11-26）：req/resp body 4.5MB（372KB bundle 足够直出），Hobby duration 300s max，Node/Python/Bun 默认 300s；大包才需对象存储。
